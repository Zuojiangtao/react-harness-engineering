# ADR 0003：复用边界

- 状态：已采纳
- 日期：2026-11-03

## 背景

两个模块都需要表格与表单。完全复制会漂移，过早抽象会造出难维护的"低代码引擎"。

## 决策

分两层处理：

1. **展示型组件**（DataTable、ResourceForm、FilterBar）：形状由 UI 范式决定，先建、再用真实需求校准；第二个模块只允许扩展 props，不允许改写既有语义。
2. **编排型逻辑**（useResourceList）：差异未知，必须先在客户模块直写，订单模块出现后再抽，并回头改客户模块。抽取提交单独成 commit，作为复用证据。

封顶三层：原语（antd）→ 模式（DataTable/ResourceForm）→ 资源 hook。**不做**配置驱动的 CRUD 引擎/DSL。

## 后果

- 正面：抽象有第二个调用点校准；新增同类模块目标 ≤ 1 小时且不改 `shared/`。
- 负面：第一个模块会有一次返工（可接受，且是证据）。
- 判断标准：如果加一个模块需要改 `shared/` 的接口语义，说明抽象错了，回到调用点重新看差异。
